One mapping, end to end

We follow one small path through the XML: raw orders in, STG_ORDERS out. It is short, but it touches every piece: a PC Source, three kinds of box, a PC Target, and the session and workflow that run it.

The path lives inside mapping m_FL_JS_STAGING_FULL L90, which writes 6 PC Targets. Here we look at the orders path only. All XML on this page was pulled from the file by a script. Attributes are trimmed to the ones that matter, and line numbers open GitHub.

1 · Who runs it: workflow and session

The workflow runs tasks in order. Each session runs one mapping. Our path sits in the first session.

What the session adds

m_FL_JS_STAGING_FULL L811
Writes STG_ORDERS through
connection STG_Jaffleshop L4587. The session itself says MART_Jaffleshop L912, but the workflow's task instance overrides it, and the override wins. (Only names; the details live outside the file.)
Load type
Bulk L913
Truncate target first?
The session option says NO L919, but the target's Pre SQL empties it anyway: TRUNCATE TABLE STG.STG_ORDERS L541. So every run is a full reload.
Treat source rows as
Insert L995

None of this changes what is computed. It is about how rows are written. dbt handles that with materialization, which is still an open question.

-- Generated from mapping m_FL_JS_STAGING_FULL, PC Target STG_ORDERS
-- Path: RAW_ORDERS → SQ_RAW_ORDERS → EXP_ORDERS → SRT_ORDERS → STG_ORDERS

with sq_raw_orders as (
    -- Source Qualifier SQ_RAW_ORDERS (XML L161–180): no override, no filter
    select id, customer, ordered_at, store_id, subtotal, tax_paid, order_total
    from {{ source('raw', 'raw_orders') }}
),

exp_orders as (
    -- Expression EXP_ORDERS (XML L106–125)
    select
        id                            as order_id,
        customer                      as customer_id,
        store_id                      as location_id,
        date_trunc('day', ordered_at) as ordered_at_day,
        subtotal / 100                as subtotal,
        tax_paid / 100                as tax_paid,
        order_total / 100             as order_total,
        subtotal                      as subtotal_cents,
        tax_paid                      as tax_paid_cents,
        order_total                   as order_total_cents
    from sq_raw_orders
)

-- Sorter SRT_ORDERS (XML L513–533) dropped: row order has no meaning in a table.

select
    order_id,
    customer_id,
    location_id,
    ordered_at_day,
    subtotal          as subtotal_cents,     -- FLAG: dollars into a *_CENTS column (XML L608)
    tax_paid          as tax_paid_cents,     -- FLAG: XML L609
    order_total       as order_total_cents,  -- FLAG: XML L610
    subtotal_cents    as subtotal,           -- FLAG: cents into a dollar column (XML L611)
    tax_paid_cents    as tax_paid,           -- FLAG: XML L612
    order_total_cents as order_total         -- FLAG: XML L613
from exp_orders

Two lessons for check 3 (matching the reference):

    
1. A faithful converter will not match the reference on these 6 columns. That's expected, so the comparison has to know about flags.

    2. Column names differ too: ordered_at_day here (from the PC Target) and ordered_at in jaffle-shop. The comparison needs a column-name map.
