PowerCenter → dbt explainer

PowerCenter → dbt converter

PowerCenter saves a data pipeline as an XML drawing of boxes and wires. dbt does the same job with plain SQL files. We built a tool, pc2dbt, that reads the XML and writes the SQL.

Where it stands (22 Nov 2026, after step 4). All 3 mappings convert into 16 dbt models, and dbt builds all 16 on DuckDB from jaffle-shop's seed data. out/flags.md lists 79 flags, 21 left-out items and nothing that couldn't be converted. Every difference from jaffle-shop has a listed reason, and the 21 facts computed from the raw seed all agree.

The three parts

Input: the XML

A mapping is a chain of boxes (transformations). Connectors join one column to the next.

The session and workflow only say when things run, not what they compute.

See one mapping, piece by piece →

Converter: five steps

Turn the drawing into a graph, follow it back from each target, and turn every box into one SQL step (a CTE).

Hard parts: Informatica's own formula language, and boxes with no direct SQL twin.

Step through the five steps →

Output: dbt models

Each model is one select. A table written by one mapping and read by the next becomes a ref().

When the XML looks wrong, the SQL copies it and carries a flag.

How we know the output is right

The first three decisions

D1 · Follow the connectors, not the names. When the XML looks wrong, copy what it does and add a flag. Don't fix it. First case: STG_ORDERS gets dollars in its *_CENTS columns L608–613. See it. There are 4 such places in all; the input page lists them.

D2 · The reference is dbt-labs/jaffle-shop, not jaffle_shop_duckdb. The XML's 6 raw tables match it, and the demo README links it.

D3 · The workflow's command task holds a plaintext credential. We never show, copy or commit it. The demo XML stays out of git.

Open questions, now decided

All 19 decisions were made on 21 Nov 2026; the full list is on the Decisions page. The four questions below were among them.

O1 · How do we run jaffle-shop on DuckDB? Its main branch needs dbt 2.0 or newer, and its README doesn't list DuckDB. We tested three ways and all three built it (49 nodes passed). One has to be chosen.

Decided (Q1): dbt 1.12 on the pinned commit 7d0d8de.

O2 · One dbt model per PC Target? This is the plan, because one model builds exactly one table. The staging mapping alone would give 6 models.

Decided (Q4): yes, one model per PC Target, with shared boxes repeated.

O3 · Load behaviour. The session says Truncate target table = NO L919, but every target's Pre SQL empties it first, e.g. TRUNCATE TABLE STG.STG_ORDERS L541. So PowerCenter fully reloads every table on each run, which is what a dbt table does too.

Decided (Q9): each model is a table, rebuilt on every run.

Corrected on 21 Nov 2026: this first said PowerCenter adds rows on every run. That missed the Pre SQL.

O4 · Folder layout of the generated models, and which language the converter is written in.

Decided (Q2, Q8): Python with pytest, and one folder per mapping.
